## 1.38.0.1

- PiP（Chrome / Edge）とバックグラウンド再生設定など、上流の更新を取り込み
- 上流バージョン変更に合わせてアドオン改訂番号を `.1` に戻した

## 1.37.0.1

- 上流 danything/denpa を 1.29.1 から 1.37.0 に更新
- ライブ・追っかけ再生の音声選択、MPEG-2 のブラウザー内再生など上流の再生機能追加を取り込み
- v1.32.0 で削除されたテレビの VLC への転送機能を README / DOCS に反映
- アドオン改訂番号は上流バージョン変更に合わせて `.1` に戻した

## 1.29.1.1

- 上流 danything/denpa を 1.29.0 から 1.29.1 に更新
- pipe を 8MiB にも1MiBにも広げられなかったとき、現在のpipeサイズと uid ごとの上限に関する手掛かりを agent のログに出す上流修正を取り込み
- HAOSで必要だった `SYS_RESOURCE` は引き続き付与

## 1.29.0.1

- 上流 danything/denpa を 1.28.0 から 1.29.0 に更新
- 同一シリアルの PX-M1UR / PX-S1UR の識別と BS/CS 標準局の登録を上流へ移し、アドオン側の px4 ラッパー・seed・jq 起動処理を削除
- 公式 AIO イメージを継承するだけの Dockerfile に縮小
- 録画先を `/media/DTV/denpa/recorded`・`library` から `raw`・`encoded` へ変更。既存ファイルは自動移動されず、DBの録画パスは起動時のマイグレーションで相対パスに書き換わる。録画のある環境では事前にDBをバックアップし、録画ファイルを新しい保存先へ移すこと
- `SYS_RESOURCE` は維持。HAOS実機では権限なしでpipeサイズの8MiB要求と1MiB fallbackがともに失敗した例がある

## 1.28.0.2

- 初回起動時にアドオン側で BS/CS 標準チャンネルをシード（無ければ作成し、既存種別は残して不足する種別だけ追記）。壊れた channels.json は上書きしない
- PX-M1UR / PX-S1UR など同一 USB シリアルの筐体を、px4d / px4ctl 互換ラッパーで USB 接続位置ごとに別 ID として認識（物理シリアルは偽装せず、`--usb-path` と `--instance` を使う）

## 1.28.0.1

- 上流 danything/denpa を 1.24.0 から 1.28.0 に更新
- 上流公式の denpa-aio イメージを採用し、本体・エージェントの独自組立と起動処理を削除
- 上流の Ingress 接頭辞対応に切り替え、独自の ingress.js 中継を削除
- BS/CS 標準チャンネルの登録を上流機能に移し、アドオン側のseedとjq処理を削除
- 既存の /config・/data・/media の配置と停止待ちを維持

## 1.24.0.1
